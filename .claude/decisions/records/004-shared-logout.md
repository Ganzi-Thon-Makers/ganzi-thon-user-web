# 화면 간 로그아웃 구현을 shared에서 공유한다

- 상태: accepted
- 기록일: 2026-11-20

## 맥락

로그아웃 버튼은 마이페이지 안에 있었다. 이슈 #116에서 팀 계정의 스탬프 QR 발급 화면에도 같은 세션 종료 동작이 필요해졌다.

## 결정

- 두 화면에서 `src/shared/components/LogoutButton.tsx`를 직접 사용한다.
- 로그아웃 요청은 `src/shared/api/session.api.ts`에, 성공 시 access token과 쿼리 캐시를 정리하는 mutation은 `src/shared/api/session.queries.ts`에 둔다. 성공 후 로그인 화면 이동과 실패 토스트는 버튼이 맡는다.

## 근거

로그아웃은 두 화면에서 같은 API와 세션 정리 규칙을 사용한다. 버튼과 요청을 함께 공유하면 어느 화면에서 로그아웃하든 같은 정책이 적용되고, `stamp`와 `mypage` 사이에 직접 의존성이 생기지 않는다. 로그인 화면 경로와 세션 종료 동작을 아는 앱 컴포넌트이므로 `shared/components`에 둔다.

## 고려한 대안

- 라우트에서 마이페이지의 버튼을 QR 화면에 prop으로 전달한다. 구현은 재사용할 수 있지만 세션 종료 동작을 쓰려는 화면마다 라우트가 마이페이지의 버튼을 조립해야 한다.
- QR 화면에 별도 버튼과 mutation을 둔다. 배치는 각 화면이 제어하기 쉽지만 토큰과 캐시 정리 로직이 중복된다.

## 영향 범위

마이페이지와 스탬프 QR 발급 화면의 로그아웃 진입점, 공용 버튼과 요청·mutation. 엔드포인트와 응답 계약은 [인증 API 문서](../../references/api/auth.md)에 기록한다.

## 검증 또는 재검토 조건

버튼 테스트에서 성공 시 세션 정리와 로그인 화면 이동, 실패 시 토스트와 재시도를 확인한다. 화면별 세션 종료 정책이 달라지면 공유 범위를 재검토한다.
