# 사용자 에러 문구는 프론트 문구를 기본으로 한다

- 상태: accepted
- 기록일: 2026-11-11

> **구현 상태 (2026-11-11 확인): 미구현.** `src/shared/api/error.ts`의 `toApiError()`가 HTTP 에러에서 백엔드 `body.message`를 그대로 쓴다. 타임아웃·네트워크·알 수 없는 에러는 이미 프론트 문구다.

## 맥락

백엔드 에러 메시지는 개발자용이거나 상태 코드 문자열(`Request failed with status code 400`)인 경우가 많고, 5xx 문구는 사용자에게 의미가 없다. 백엔드 에러 형식은 아직 확정되지 않았다.

## 결정

- 사용자에게 보이는 문구는 프론트에서 정한 문구를 기본으로 한다(상태 코드·에러 코드별).
- 백엔드 `message`는 사용자에게 의미 있는 비즈니스 에러(예: 이미 가입된 이메일)에서만 명시적으로 opt-in해서 쓴다.
- 입력 검증 오류는 가능하면 입력 옆 표시와 버튼 비활성화로 미리 막는다.

## 근거

문구 품질을 프론트가 통제하고, 백엔드 문구 변경이 화면에 그대로 새는 것을 막는다.

## 고려한 대안

- 백엔드 message 그대로 노출: 백엔드가 사용자용 문구를 보장할 때만 맞다. 현재 합의 없음.

## 영향 범위

`shared/api/error.ts`(`toApiError`), `shared/components/PageError.tsx`, 이후 mutation 실패 안내(toast).

## 검증 또는 재검토 조건

- 백엔드 에러 형식(`ErrorBody`)이 확정되면 `toApiError`를 고치고 `error.test.ts`에 케이스를 추가한 뒤 구현 상태를 갱신한다.
- 백엔드가 사용자용 문구를 책임지기로 합의하면 재검토한다.
