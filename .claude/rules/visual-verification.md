# 시각 검증 규칙

Figma와 실제 렌더를 비교할 때는 눈에 띄는 차이보다 사용자가 읽고, 이해하고, 조작하는 흐름에 영향을 주는 차이를 우선한다.

## 입력

- 대상 Figma node URL과 frame 크기
- 실제 route 또는 컴포넌트의 렌더 화면
- 확인에 쓴 viewport와 관련 diff

둘 다 있어야 일치 여부를 판정한다. 하나가 없으면 통과로 쓰지 않고, 없는 입력과 코드로 확인한 범위를 나눠 보고한다.

## 비교 순서

1. 화면 순서, 정보 위계, 핵심 버튼, 이미지·문구의 존재와 배치
2. 컨테이너 폭, 여백 리듬, grid, 정렬, 줄바꿈처럼 읽기 흐름에 영향을 주는 요소
3. 색·타이포가 `globals.css` 토큰과 맞는지
4. 좁은 화면의 가로 overflow, 잘림, 겹침, 터치 대상, 키보드 흐름
5. 모션은 근거가 있을 때만 비교하고, reduced motion에서도 콘텐츠와 조작이 남는지 확인

Figma frame 크기를 알면 그 크기를 우선한다. 모바일 디자인이 없으면 모바일 완성도를 주장하지 않고, 확인한 좁은 viewport와 공백을 남긴다.

## NEEDS_REVISION 기준

- 핵심 정보·버튼이 빠졌거나 순서가 바뀌어 이해 흐름이 달라짐
- 콘텐츠가 잘리거나 가로로 넘치고, 겹치거나 조작할 수 없음
- 밀도·정렬·자산 선택이 정보 위계를 실질적으로 바꿈
- 토큰 밖 임의 색·간격으로 디자인 시스템과 어긋남
- 필수 모션이 콘텐츠 접근을 막거나 reduced motion 대체가 없음

안티앨리어싱, 서브픽셀, OS 글꼴 렌더링 차이와 근거 없는 취향은 결함으로 기록하지 않는다.

## 증거와 보고

- Figma node, route·컴포넌트, viewport, 사용한 화면 근거를 함께 남긴다.
- 발견 사항은 심각도, 차이, 사용자 영향, 최소 수정 방향 순서로 쓴다.
- 임시 캡처와 비교 산출물은 요청이 없으면 저장소에 추가하지 않는다.
