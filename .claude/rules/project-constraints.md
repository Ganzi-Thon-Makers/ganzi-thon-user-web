# 프로젝트 제약

구현·리뷰·설정 등 프로젝트 변경 전반에 적용한다.

## 범위와 사실

- 모바일 웹이 주 대상이다. 넓은 화면은 깨지지 않게만 한다.
- 새 사용자 흐름이나 페이지를 추가할 때는 목적, 사용자 경로, 디자인·명세를 먼저 확인한다.
- 버튼·폼·링크는 확인된 목적지나 사용자가 승인한 동작이 있을 때만 실제 흐름에 연결한다. 없으면 연결하지 않고 공백으로 보고한다.
- 확인할 수 없는 문구·수치·정책을 임의 카피로 채우지 않는다. 디자인의 확정 문구를 쓰거나 근거를 요청한다.
- 제공받지 않은 로고·사진·외부 서비스 자산을 쓰지 않는다. 임시 자산이 필요하면 임시임이 드러나게 한다.

## 기술

- `pnpm`만 쓴다.
- Next.js App Router와 Tailwind CSS v4를 유지한다. Tailwind v3 설정 파일, Pages Router, Vite·React Router 전용 설정을 추가하지 않는다.
- 새 라이브러리는 추가 전에 사람에게 묻는다. 그 전에 표준 라이브러리 → 브라우저·CSS 기본 기능 → 이미 설치된 패키지로 해결되는지 순서대로 확인한다.
- 외부 이미지 호스트, 분석 스크립트, 외부 폰트, iframe은 개인정보·성능·운영 책임자가 확인된 경우에만 추가한다.

## 디자인

- Figma의 확정된 레이아웃·문구·에셋을 우선하고, 부족한 부분은 추측으로 채우지 않는다.
- 외부 참고 서비스는 정보 구조와 상호작용 방향만 참고하고 결과물을 복제하지 않는다.
